# Retrove 开发清单

[English](./checklist.md)

> 按阶段推进的实现清单。完成标准写在每项后面；开发时勾选并同步更新状态。  
> 设计依据：[开发文档.md](./开发文档.md)。

**技术栈定案：** Go 后端 · Vue3 + Naive UI 前端 · SQLite · Docker · 首期 ScreenScraper + 本地词典 · 导出至 `/app/data/export`。  
**身份定案：** 主机用包内 ROM hash，街机用 zip hash；一文件一游戏；中文名以数据库为准，词典文件只做导入/备份；识别先本地再 ScreenScraper。  
**路径定案：** 容器内持久化目录均为 `/app/config`、`/app/data`、`/app/roms`；文档在根目录 `docs/`；本地用根目录 `Makefile` 跑前后端。

## Phase 2 — 扫描与 hash 身份

- [x] 遍历 ROM 根目录，按平台 `directory` 归属，扩展名过滤
- [x] 主机：`hash_mode=content` 时对 zip 内主 ROM 算 CRC32/MD5/SHA1；街机/archive 算 zip 本身；size+mtime 未变则跳过重算
- [x] hash 命中 → 更新 `path`/`filename`（改名探测）
- [x] hash 未命中 → 插入 `rom_files`，并新建一条 `game`（一文件一游戏）
- [x] 本轮未出现的旧路径 → `missing=true`
- [x] 同 hash 另一路径仍存在 → `duplicate` 报告
- [x] `POST /api/v1/jobs/scan`、`GET /api/v1/jobs`、`GET /api/v1/jobs/{id}`
- [x] 扫描报告：added / renamed / missing / duplicate / skipped / scanned

**完成标准：** 单元测试覆盖改名合并与 zip 内容 hash；接口可触发异步扫描。

## 首期验收清单（Demo 路径）

1. `docker compose up` 启动  
2. 挂载现有中文 Pegasus ROM 库  
3. 扫描成功，改名再扫身份不变  
4. 导入 Pegasus，中文名可见  
5. 配置 ScreenScraper，刮到至少 1 张封面  
6. 词典校正/锁定中文名  
7. 导出 Pegasus 到 `app/data/export`（容器内 `/app/data/export`）  
8. 管理台可完成上述操作而无需改代码  

全部满足则首期关闭，再开 Phase 8/10。
