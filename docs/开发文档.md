# Retrove 开发文档

[English](./development.md)

> 面向中国用户的自托管复古游戏 ROM 收藏库。对标 RomM 的「扫描 → 识别 → 刮削 → 管理 → 导出」，以中文名与国内前端生态为一等公民。  
> 本文描述整体设计与功能说明，具体任务见 [开发清单.md](./开发清单.md)，部署见 [部署指南.md](./部署指南.md)。

---

## 1. 产品定位

Retrove 帮助用户：

- 管理多机型 ROM 目录（FC / SFC / MD / FBNeo / MAME …）
- 用内容 hash 稳定识别文件（改名不丢元数据）
- 以天马导入的中文名、简介、开发商、box、logo、预览视频为主数据；翻译补英文名；刮削只补天马没带来的空位
- 在 Web 管理台改单款游戏，并写回天马 ROM 名、元数据字段和媒体目录
- 导出为天马、EmuELEC、iisu、Cocoon、Pegasus 等前端可用的数据表与媒体布局

**非目标（首期不做）：** 模拟器本体、在线联机、捆绑分发 ROM、多租户 SaaS。

---

## 2. 设计原则

1. **ROM 文件是真相源**  
   二进制只存在于磁盘；数据库只存索引、元数据、任务状态。删库后可重新扫描 + 导入词典/Pegasus 重建。

2. **文件身份 = 内容 hash，不是文件名**  
   同时保存 CRC32、MD5、SHA1。改名/挪路径只更新路径字段。  
   - 主机（FC / SFC / MD 等）：算**压缩包内 ROM** 的 hash（身份不随重新打包变化）。  
   - 街机（MAME / FBNeo）：算 **zip 文件本身** 的 hash。

3. **一个文件一条游戏**  
   美版、日版、汉化、Hack 各自成条。`SFC` 与 `SFC hack` 靠目录区分，不自动合并。

4. **中文名以数据库为准**  
   页面改的是 SQLite（`games` / `aliases`）。`/app/config/dictionaries/` 只用于导入和备份导出。  
   识别顺序：已入库 → 本地 Pegasus / 词典 → ScreenScraper 补英文与封面 → 未识别。  
   通用机器翻译不做默认路径；LLM 为后续可选能力。

5. **内部统一模型，前端只做适配器**  
   所有导出目标读同一套 `games` / `rom_files` / `media`，由 exporter 写出各自格式。

6. **默认不自动改磁盘文件名**  
   改的是库内 `title_zh`；物理 rename 需显式开关。Arcade 默认禁止自动改名。

## 3. 技术栈（已定案）

| 层级 | 选型 |
|------|------|
| 后端 | Go |
| 前端 | Vue 3 + TypeScript + Vite + Naive UI |
| 数据库 | SQLite（WAL 模式） |
| 部署 | Docker / Docker Compose |
| 首期刮削 | ScreenScraper + 本地词典 |
| 后续可选 | IGDB、LLM 名称清洗、Redis 任务队列 |

单机自用场景下 SQLite 足够；并发写通过单 worker / 串行任务约束。若日后多人高并发再评估 PostgreSQL。

```text
┌─────────────────────────────────────────────────────────┐
│  Vue3 + Naive UI（管理台）                               │
└───────────────────────────┬─────────────────────────────┘
                            │ HTTP JSON API
┌───────────────────────────▼─────────────────────────────┐
│  Go API + 内置/旁路 Worker                               │
│  scan │ match │ scrape │ dictionary │ export │ jobs     │
└───────┬─────────────────┬─────────────────┬─────────────┘
        │                 │                 │
   ┌────▼────┐   ┌──────▼──────┐  ┌──────▼──────┐
   │ SQLite  │   │ /app/roms   │  │ /app/data   │
   │(app/data)│   │ ROM 库      │  │ media/      │
   └─────────┘   └─────────────┘  │ export/     │
                                  │ cache/      │
                                  └─────────────┘
                      ┌──────────────┐
                      │ /app/config  │ 配置、词典、密钥
                      └──────────────┘
```

### 4.1 后端模块（逻辑分包）

| 模块 | 职责 |
|------|------|
| `api` | HTTP 路由、单用户登录会话、DTO |
| `scan` | 遍历 ROM 目录、增量 hash、路径变更检测 |
| `match` | hash / 词典 / 文件名清洗后的识别 |
| `scrape` | ScreenScraper 客户端、限流、结果写入 |
| `dictionary` | 词典文件导入/导出；运行时查询走数据库 |
| `import` | 导入现有 Pegasus `metadata.pegasus.txt` |
| `export` | Pegasus（天马） / EmuELEC / iisu / Cocoon 适配器 |
| `media` | 媒体下载、落盘、`/app/data/media` 索引 |
| `jobs` | 后台任务状态（扫描/刮削/导出） |
| `store` | SQLite 访问与迁移 |

### 4.2 前端模块（页面）

| 模块 | 功能 |
|------|------|
| 库总览 | 统计、缺封面/未识别/待确认、快捷入口 |
| 平台库 | 平台树 + 游戏列表/卡片、筛选排序 |
| 游戏详情 | 中英名称、简介、ROM 文件、媒体；保存后写回天马 ROM 名、元数据字段和媒体目录 |
| 扫描与识别 | 进度、新增/删除/改名 diff、批量接受匹配 |
| 刮削中心 | ScreenScraper 账号、按缺项/平台刮削、失败重试 |
| 别名工作台 | 本地词典浏览、批量套用、待审建议 |
| 媒体库 | 缺失列表、手动上传/替换 |
| 导出 | 选择目标与平台，输出到 `data/export` |
| 平台映射 | 目录名 ↔ 内部平台 ↔ 各前端系统 ID |
| 系统设置 | 路径、密钥、是否允许 rename、日志 |
| 任务与日志 | 任务列表、取消、错误详情 |

首期可先交付：总览、平台库、详情、扫描、别名、Pegasus 导出、设置、任务。

## 5. 数据模型（概念）

### 5.1 核心实体

- **platforms**  
  内部平台码、显示名、目录匹配规则、扩展名、各前端映射、是否禁止自动改名（Arcade）。

- **games**  
  一条游戏对应一个主文件。字段：`title_zh` / `title_en` / `title_ja`、简介、开发商、发行年、锁定标记、刮削外部 ID。

- **rom_files**  
  相对路径、文件名、size、crc32、md5、sha1、`game_id`、missing。  
  **业务唯一：** 内容 hash（主机为包内 ROM，街机为 zip）+ size。同 hash 多路径视为重复副本。

- **aliases**  
  存在数据库：平台 + 英文名/俗称/历史文件名 → `game_id`。词典文件导入后写入此表。

- **media_assets**  
  类型（box / title / screenshot / …）、相对 `data/media` 的路径、来源。

- **scrape_cache**  
  按 hash 或外部 ID 缓存 ScreenScraper 原始/规范化结果，减少重复请求。

- **jobs**  
  类型、进度、状态、错误信息、时间戳。

### 5.2 ROM 唯一性与改名

```text
扫描到文件
  → 若 size+mtime 未变且路径已知：跳过重算
  → 主机：解压读取主 ROM，计算 crc32 / md5 / sha1
    街机：对 zip 文件本身计算
  → 按该 hash(+size) 查 rom_files
       命中：更新 path / filename（识别为 rename/move）
       未命中：插入新 rom_files，并新建一条 game（一文件一游戏）
  → 库中有记录但本轮未扫到：标 missing（不立刻删元数据）
```

名称挂在 `games` 与 `aliases` 上，不作为文件主键。

### 5.3 识别流水线

1. hash 已关联 `game` → 继承已有中文名与刮削结果  
2. 天马导入（`metadata.pegasus.txt` + `media/{ROM 主文件名}/`）覆盖中文名、简介、开发商、box、logo、预览视频  
3. 翻译模块把中文名写成英文名（已有英文名则跳过），供刮削查询  
4. 刮削只补天马没带来的空位：IGDB → ScreenScraper → SteamGridDB；已有字段和媒体不替换  
5. 仍失败 → `unidentified`，可在详情页手工修改并写回天马文件

## 6. 功能说明

### 6.1 扫描

- 递归扫描 `/app/roms`（或配置的 ROM 根目录），按一级（或约定）子目录归属平台。
- 支持扩展名白名单；忽略隐藏文件与导出产物。
- 产出扫描报告：新增 / 改名 / 缺失 / 重复 hash。

### 6.2 本地词典

- 运行时只读数据库中的 `aliases` 与 `games.title_zh`。
- `/app/config/dictionaries/` 用于导入、以及从库导出备份。
- 条目至少包含：平台、英文标准名或 hash、中文名、可选别名。
- 天马导入写入 `games` 与 `aliases`，并覆盖已有中文名、简介、开发商。
- 别名工作台改数据库。刮削不替换已有中文名、简介、开发商、英文名和媒体。

### 6.3 刮削源（ScreenScraper + IGDB + SteamGridDB）

批量刮削按已配置源自动串联，只补空位，不替换已有值。源的顺序不变：

1. **IGDB**（主源，可选）：Twitch Client ID/Secret。用翻译得到的英文名 + `platforms.yaml` 的 `igdb_id` 过滤平台；补仍为空的英文名、简介、开发商、年份、封面、截图和标题图。
2. **ScreenScraper**（可选）：开发者/用户凭据存 `/app/config`。优先内容 hash，失败再文件名；只补 IGDB 仍缺的元数据与媒体。
3. **SteamGridDB**（可选）：API Key。只补仍缺失的媒体（竖版封面、标题图、Logo；无截图时可用标题图）。

没有英文名的游戏整款跳过。预览视频不刮。刮削结果只写入数据库和 `/app/data/media/{platform}/{game_id}/`，不回写天马目录。遵守各 API 限额；失败入 jobs 可重试。  
**不**用刮削结果自动改 ROM 文件名。设置页一级只展示各源状态，凭据在二级弹窗填写。

### 6.4 导入天马（Pegasus 元数据）

天马资料就是各平台目录下的 `metadata.pegasus.txt` 和 `media/{ROM 主文件名}/`。再次导入以这些文件为准，覆盖库里的对应内容。

- 用 `file:` 对齐已扫描的 `rom_files`。没有 ROM 记录的条目跳过。
- `game:` → 中文名，`description:` → 简介，`developer:` → 开发商。
- 媒体目录跟 ROM 主文件名，不跟 `game:` 标题。`boxFront.*` → box，`logo.*` → logo，`video.*` → 预览视频，复制到 `data/media/{platform}/{game_id}/`，来源记为 `pegasus`。某一项不存在时不删除库里已有的那一份。

详情页保存单款游戏时写回这些文件：

- 改中文名：主机平台把 ROM 改名为 `{新中文名}{原扩展名}`，同步 `rom_files`，并改元数据的 `game:` / `file:`。整个 `media/{旧主文件名}/` 改名，预览视频跟着走。目标 ROM 或媒体目录已存在时取消改名。街机 `rename_policy: deny` 不改 ROM 和媒体目录名，只改元数据里的 `game:`。
- 改简介或开发商：只改这一条的对应字段，不重写整份元数据。
- 在详情页更换 box / logo / 预览视频：覆盖该目录的 `boxFront.*` / `logo.*` / `video.*`。截图、标题图、英文名只留在游戏库。刮削不导入、不替换预览视频。

### 6.5 导出

- 统一从 DB 读取，写入 **`/app/data/export/<target>/`**（不默认覆盖用户 ROM 旁文件，除非设置允许）。
- 目标：
  - **Pegasus**：`metadata.pegasus.txt` + 媒体布局（与现有库兼容，优先实现）
  - **EmuELEC / EmulationStation**：`gamelist.xml` + 媒体约定
  - **iisu / Cocoon**：各自数据表与媒体规则（分适配器实现）
- 每次导出生成报告（成功/跳过/失败）。

### 6.6 管理台能力摘要

- 搜索（中英文名、文件名）
- 编辑单款游戏，并把中文名、简介、开发商、box、logo、预览视频写回天马文件
- 手动上传封面和预览视频（box / logo / video 同时写回天马媒体目录）
- 触发扫描 / 刮削 / 导出
- 查看重复 ROM、缺失文件、未识别列表

### 6.7 登录

- 只允许一个用户。库里还没有用户时，管理台只显示注册；已有用户后不再提供注册入口，再次注册会被拒绝。
- 注册字段：用户名、邮箱、密码、确认密码。密码至少 8 位，两次输入必须一致。
- 登录使用用户名和密码。会话放在 HttpOnly Cookie 中。
- 健康检查 `GET /api/v1/health` 不需要登录。

### 6.8 后续可选（文档占位，非首期）

- IGDB 等第二刮削源  
- LLM 结构化改名建议（待审队列，默认不改磁盘名）  
- 多用户  
- Redis 分布式队列

## 7. 目录与 Docker 挂载

容器工作目录为 `/app`；持久化目录均挂在 `/app/` 下：

| 宿主机（建议） | 容器内 | 内容 |
|----------------|--------|------|
| `./app/config` | `/app/config` | `config.yaml`、词典、ScreenScraper 密钥、`retrove.db` |
| `./app/data` | `/app/data` | `media/`、`export/`、`cache/` |
| `./app/roms` | `/app/roms` | ROM 库 |

说明：

- 源码在仓库根目录：`cmd/`、`internal/`、`web/`。`app/` 只放运行时的 `config/`、`data/`、`roms/`，不放源码。  
- 镜像内放 Go 二进制（已 embed 管理台 SPA）与默认 `platforms.yaml` / `config.example.yaml`；Compose 只挂上述三个子目录，不要把整个仓库挂进容器。  
- 首次启动若挂载卷缺少 `platforms.yaml` / `config.yaml`，entrypoint 会从镜像默认值种子写入。  
- 容器内管理台监听 `:5180`（对外映射），API `:5080`（仅容器内，UI 转发 `/api`）。  
- 文档位于仓库根目录 **`docs/`**。本地用根目录 **`Makefile`** 启动前后端。  
- 导出固定写到 **`/app/data/export`**。媒体在 **`/app/data/media`**。

## 8. API 设计要点（约定）

- REST JSON，前缀如 `/api/v1`。  
- 资源示例：`/platforms`、`/games`、`/roms`、`/jobs`、`/scrape`、`/export`、`/dictionary`。  
- 长任务一律创建 job 并返回 `job_id`，前端轮询或 SSE（首期轮询即可）。  
- 错误响应统一 `{ "code", "message", "details?" }`。  

具体路由表在实现阶段按 [开发清单](./开发清单.md) 补齐 OpenAPI。

## 9. 平台映射

使用 `/app/config/platforms.yaml`（或等价）维护：

- 目录名（如 `SFC`、`FBNEO STG`）→ 内部 `platform_id`
- 扩展名列表
- ScreenScraper system id
- IGDB platform id
- 各导出目标的系统/文件夹名
- `rename_policy`: `allow` | `deny`（Arcade 为 `deny`）

现有仓库中的 `roms/*/metadata.pegasus.txt` 作为平台与中文数据的重要参考样本。

---

## 10. 安全与合规

- 不在日志中打印完整 API 密钥。  
- 容器以可配置 `PUID/PGID` 运行，避免 NAS 权限问题。  
- 项目只管理用户自有 ROM；发行与文档不提供 ROM 下载。  
- 遵守 ScreenScraper 等第三方 ToS 与速率限制。
