# Retrove 部署指南

[English](./deployment.md)

> 本地开发调试与 Docker 部署说明。设计见 [开发文档.md](./开发文档.md)，任务见 [开发清单.md](./开发清单.md)。  
> 工程骨架落地前，本文先约定目录、环境变量与推荐流程；实现后按实际命令微调，但挂载约定不轻易改。

---

## 1. 目录约定

- **文档**：仓库根目录 `docs/`（本文所在位置）。  
- **本地开发**：仓库根目录 `Makefile` 启动前后端。  
- **Docker**：容器工作目录为 **`/app`**，持久化数据挂在 `/app/` 下。

建议仓库结构：

`app/` **只放运行时数据**（配置、数据库、媒体、导出），不放源码。源码在仓库根目录，打进镜像；容器里只把这三个目录挂到 `/app` 下。

```text
retrove/                      # 代码仓库根（Go module 根）
├── Makefile
├── go.mod
├── docs/
├── docker-compose.yml
├── cmd/retrove/              # 后端入口
├── internal/                 # 后端业务（不对外）
├── web/                      # Vue3 前端
└── app/                      # 仅运行时，不放源码
    ├── config/               # 挂载 → /app/config
    ├── data/                 # 挂载 → /app/data
    └── roms/                 # 挂载 → /app/roms
```

ROM 库实际放在 **`app/roms/`**（已有 Pegasus 元数据），与 config、data 一样属于运行时目录。

| 宿主机 | 容器路径 | 用途 |
|--------|----------|------|
| `./app/config` | `/app/config` | 配置、平台映射、词典、API 密钥、SQLite |
| `./app/data` | `/app/data` | 媒体、缓存、**export** |
| `./app/roms` | `/app/roms` | ROM 文件（只扫描此树） |

导出写入：**`/app/data/export/<target>/`**（宿主机即 `app/data/export/`）。

## 2. 配置文件

### 2.1 `app/config/config.yaml`（示例结构）

```yaml
server:
  listen: ":5080"

paths:
  roms: /app/roms
  data: /app/data
  config: /app/config

sqlite:
  path: /app/config/retrove.db
  # WAL 由程序启动时 PRAGMA 开启

screenscraper:
  dev_id: ""
  dev_password: ""
  user_ss: ""
  user_password: ""
  softname: Retrove
  # 注意限额；留空则刮削功能不可用，其余功能正常

scan:
  rehash_on_mtime_size_change: true
  follow_symlinks: false

export:
  root: /app/data/export
  # 默认不写回 /app/roms 旁，避免覆盖用户手写 metadata

security:
  allow_rom_rename: false   # 物理改名总开关；Arcade 仍受平台 deny 约束

log:
  level: info
```

### 2.2 密钥

- ScreenScraper 凭据只放 `app/config/`，**不要提交 git**。  
- 可用 `config.yaml` + 文件权限，或环境变量覆盖（实现时支持其一并在此文档写明）。

### 2.3 环境变量（建议）

| 变量 | 含义 |
|------|------|
| `PUID` / `PGID` | 容器内读写挂载目录的用户（NAS 常用） |
| `TZ` | 如 `Asia/Shanghai` |
| `RETROVE_CONFIG` | 配置文件路径。本地默认 `./app/config/config.yaml`，容器为 `/app/config/config.yaml` |
| `RETROVE_LISTEN` | 监听地址，本地与容器均为 `:5080` |
| `RETROVE_ROMS` / `RETROVE_DATA` / `RETROVE_CONFIG_DIR` | 覆盖 yaml 里的路径。`make backend` 会设成本地 `./app/...` |
| `RETROVE_SQLITE` / `RETROVE_EXPORT` | 覆盖数据库文件与导出目录 |
| `RETROVE_LOG_LEVEL` | 覆盖日志级别 |

## 3. Docker 部署（目标形态）

### 3.1 Compose 示意

```yaml
services:
  retrove:
    image: retrove:local   # 或 build: .
    working_dir: /app
    ports:
      - "5080:5080"
    environment:
      TZ: Asia/Shanghai
      PUID: "1000"
      PGID: "1000"
      RETROVE_CONFIG: /app/config/config.yaml
    volumes:
      - ./app/config:/app/config
      - ./app/data:/app/data
      - ./app/roms:/app/roms
    restart: unless-stopped
```

单容器内建议：Go 提供 API，并在同进程跑任务队列（goroutine worker）。前端静态资源由 Go embed 或同镜像反代（实现时二选一，保持「一个服务端口」优先）。

### 3.2 首次启动

```bash
mkdir -p app/config/dictionaries app/data/media app/data/export app/data/cache
cp app/config/config.example.yaml app/config/config.yaml
# 编辑 ScreenScraper 与端口等

docker compose up -d --build
# 浏览器打开 http://localhost:5080（API）。管理台开发请用 make dev，地址 http://127.0.0.1:5180
```

### 3.3 数据与备份

| 备份项 | 必要性 |
|--------|--------|
| `app/config/retrove.db` | 必须（元数据） |
| `app/config/` | 必须（词典与密钥） |
| `app/data/media/` | 建议（可重刮，费时费配额） |
| `app/data/export/` | 可选（可再导出） |
| `app/roms/` | 用户资源，按自己的备份策略 |

恢复：停服务 → 还原 `app/data` + `app/config` → 再启动 → 必要时重新扫描对齐路径。

### 3.4 权限问题（NAS）

- 宿主机目录属主与 `PUID/PGID` 一致。  
- 若只读 ROM：可把 `/app/roms` 对应卷挂为 `:ro`，并保持 `allow_rom_rename: false`。

## 4. 本地调试（开发机 + Makefile）

日常开发在**仓库根目录**用 `Makefile` 启动，不必先起 Docker。

### 4.1 依赖

- Go（与 `go.mod` 版本一致）
- Node.js LTS（前端）
- `make`
- 可选：Docker（验证镜像 / 接近生产部署）

### 4.2 推荐 Makefile 目标

落地后在根目录提供（名称可微调，但语义保持）：

| 目标 | 作用 |
|------|------|
| `make dev-backend` | 启动 Go API（读 `app/config/config.yaml`，本地 paths 指向 `./app/roms`、`./app/data`） |
| `make dev-frontend` | 启动 Vite 开发服（`web/`，端口 5180，`/api` 代理到 5080） |
| `make build` | 构建后端二进制 + 前端静态资源 |
| `make test` / `make lint` | 测试与检查 |
| `make docker-up` | `docker compose up -d --build` |
| `make docker-down` | 停止 compose |

首次：

```bash
mkdir -p app/config/dictionaries app/data/media app/data/export app/data/cache
cp app/config/config.example.yaml app/config/config.yaml
# 本地路径由 Makefile 用环境变量覆盖为 ./app/roms、./app/data、./app/config

# 两个终端分别执行：
make dev-backend
make dev-frontend
```

健康检查：`curl -s http://127.0.0.1:5080/api/v1/health`  
前端：http://127.0.0.1:5180

### 4.3 本地配置与 Docker 配置的差异

| 项 | 本地 `make` | Docker |
|----|-------------|--------|
| 配置文件 | `./app/config/config.yaml` | `/app/config/config.yaml` |
| `paths.roms` | `./app/roms` | `/app/roms` |
| `paths.data` | `./app/data` | `/app/data` |
| `paths.config` | `./app/config` | `/app/config` |

可用同一份 yaml + 环境变量覆盖路径，或提供 `config.local.yaml`（勿提交密钥）。`Makefile` 应导出 `RETROVE_CONFIG` 指向本地文件。

### 4.4 SQLite 调试

- DB 文件：`app/config/retrove.db`（容器内 `/app/config/retrove.db`）  
- 推荐工具：`sqlite3` CLI 或 GUI（注意服务运行时 WAL 热连）。  

```bash
sqlite3 app/config/retrove.db "PRAGMA journal_mode; PRAGMA busy_timeout;"
sqlite3 app/config/retrove.db "SELECT COUNT(*) FROM rom_files;"
```

重置库与刮削媒体（会丢元数据/用户/任务，不删 `app/roms`）：

```bash
make docker-down   # 若在用 compose
make reset-db
# 再 make dev-backend 或 make docker-up，启动时建空库
```

### 4.5 典型调试路径

1. `make dev`，小样本只用 `app/roms/SFC` 等 1～2 个平台。  
2. 触发扫描 → 确认 `rom_files` 有 hash。  
3. **改名一个 zip** → 再扫描 → 确认同一 `sha1` 记录路径更新，而非新行。  
4. 导入该平台天马资料 → 详情页中文名、简介、box、logo、预览视频可见。再次导入会替换这些内容。  
5. 先翻译英文名，再刮削 → 只补空位；已有中文名和封面保持不变。看 `app/data/media`。  
6. 导出 Pegasus → 检查 `app/data/export/pegasus/...`。

### 4.6 日志

- 开发：`log.level: debug`  
- 刮削限额、hash 耗时、job 失败原因应可检索。  
- 禁止在日志输出密码字段。

## 5. ScreenScraper 调试注意

- 先在小样本上验证，避免全库打满配额。  
- hash 未命中时再试文件名；对照 SS 网站是否收录该 CRC。  
- 失败分类：认证错误 / 限额 / 未找到 / 网络；UI 与 job 详情应能区分。  
- `scrape_cache` 命中时应跳过重复下载（改名后不应重新拉同一媒体，除非强制刷新）。

## 6. 导出结果验收

| 目标 | 预期路径（示例） |
|------|------------------|
| Pegasus（天马） | `app/data/export/pegasus/<平台>/metadata.pegasus.txt` |
| EmuELEC | `app/data/export/emuelec/...` |
| iisu | `app/data/export/iisu/...` |
| Cocoon | `app/data/export/cocoon/...` |

容器内对应前缀均为 `/app/data/export/...`。

验收：抽查中文 `game` 名、文件相对路径、媒体是否存在；Arcade 文件名未被擅自修改。

## 7. 常见问题

**扫描很慢**  
首次需全量 hash；之后靠 size+mtime 跳过。SSD/本地盘明显快于网络挂载；可先对单平台调试。

**改名后变成新游戏**  
说明唯一键误用了路径/文件名，属实现 bug；应以 sha1+size 合并。

**中文名被刮削覆盖**  
第三方刮削不应替换已有中文名、简介、开发商、英文名、box 和 logo。若仍被改掉，属于实现问题。要改这些内容，用详情页保存（会写回天马文件），或替换天马文件后重新导入。

**容器能启动但看不到 ROM**  
检查 compose 是否把宿主机 ROM 目录挂到 **`/app/roms`**，以及 `paths.roms` 是否为 `/app/roms`。

**数据库 locked**  
确认 WAL 与 busy_timeout；避免多进程写同一 db（单 worker 写库）。

**只挂了 data + config，没挂 roms**  
需在 config 把 ROM 指到 `/app/data/roms` 并放入文件；仍推荐独立 `/app/roms` 卷。
